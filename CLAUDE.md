# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Go application that ingests Russian-language quarterly financial data and serves an interactive web UI for cross-company metric comparison. One binary:

- `cmd/plot` — HTTP server (default `:8088`) that renders the UI and chart pages, runs the fetch pipelines from `/updates` (`POST /api/fetch`, `POST /api/import-manual`; see "Primary-source fetch"), and on a timetable (see "Scheduled refresh"; `SCHEDULER_ENABLED=0` disables it). Listed banks come from the CBR's quarterly form 102/101 archives (see "Bank fetch"). The pipelines live in `internal/fetcher`.

`plot` calls `database.RunMigrations` on startup.

## Commands

```bash
# Run web server (reads env vars, see config.go for defaults)
go run ./cmd/plot

# The annual IFRS batch is on /updates (POST /api/import-manual). A data
# refresh is POST /api/fetch. JSON mirrors the old
# FETCH_* knobs: tickers, banks, all, force, quotes_only, concurrency,
# bank_from_year. Empty tickers refresh companies already in the DB; all=true is
# the full bundled registries; a ticker without an INN is looked up in MOEX ISS.
# Annual IFRS for many companies is a semicolon file (company, year, and the
# manual-form columns) posted to /api/import-manual; it writes manual_financials,
# not company_financials.
# Auth applies when AUTH_* are set.

# Disable the timetable (quotes 07:00, financials "sun 05:00" Moscow time otherwise):
SCHEDULER_ENABLED=0 go run ./cmd/plot

# Build
go build ./...

# Tests. The repository integration tests in internal/database skip unless
# TEST_DATABASE_DSN points at a THROWAWAY Postgres (they truncate its tables);
# CI runs them against a postgres service container.
go test ./...
TEST_DATABASE_DSN="host=127.0.0.1 port=55432 user=test dbname=postgres sslmode=disable" go test ./internal/database/
```

Migrations, templates and the UI assets are embedded (`embed.go`: `financialanalyzer.MigrationsFS` / `TemplatesFS` / `StaticFS`), so binaries run from any working directory.

Config is env-var only (`internal/config/config.go`): `PORT`, `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_SSLMODE`, `AUTH_USER`, `AUTH_PASSWORD`, `SCHEDULER_ENABLED`, `SCHEDULE_QUOTES`, `SCHEDULE_FINANCIALS`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Defaults target a local Postgres (`localhost:5432`, user `postgres`, password `password`, db `postgres`). `AUTH_USER`/`AUTH_PASSWORD` must be set together (`Validate` rejects one without the other), and so must `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID`.

## Architecture

**Data model.** `company_financials` is the single fact table, keyed by `(year, quarter, company)` with a `category` column and one column per metric (capitalization, revenue, net_profit, ebitda, debt, pe, roe, equity, dividends, cash, operating_profit, operating_cash_flow, capex). The flows are revenue, net_profit, ebitda, operating_profit, operating_cash_flow and capex (`analytics.IsFlow`; the upsert's annual/quarterly flip logic covers all six); the rest are point-in-time. Metric fields in `models.QuarterData` are `*float64`: **nil = not reported (NULL), non-nil zero = a real zero** (e.g. a debt-free company). Loaders set only what they know — the zero value is safe, because nil never overwrites a stored value. Build values with `models.Float(v)`; analytics reads them via `models.ValueOrNaN` (NaN is its missing-value convention, so a reported 0 stays 0 in series and snapshots). A `source` column (`models.Source*`: `rsbu`, `cbr_102`, `csv`; `smartlab` survives only on legacy rows from the removed scraper; NULL for older rows; `manual` exists only on read, see "Manual entries") records which pipeline wrote the row; every loader must set `QuarterData.Source`, and the upsert keeps the existing source when the new one is empty. `debt_source` and `cash_source` name the pipeline that wrote that column (NULL when the column is NULL); `SaveQuarterData` stamps `Source` onto a column only when this write sets it, and an empty source keeps the stored column source. `company_notes` holds free-text notes keyed by company. `source` also tells what the **flow** metrics mean (an RSBU Q4 row = the whole year, CSV/CBR rows = one quarter), so the upsert only lets a write that carries flows (any of the six above) change it — a CSV row with only dividends never relabels annual RSBU figures — and when incoming flows flip a **Q4 row between annual (rsbu) and single-quarter** meaning, the old flows and the P/E/ROE derived from them are replaced rather than merged (no row mixes annual and quarterly figures); every other source change (csv/smartlab/legacy NULL — all quarterly) merges, and stock metrics always merge. `SaveQuarterData` does an upsert that uses `COALESCE(EXCLUDED.x, existing.x)` so a row imported with only some metrics filled in won't wipe previously-imported metrics for the same quarter (a consequence: a wrong stored value can be corrected, but not cleared back to NULL, by re-importing). Rows written before the pointer change stored reported zeros as NULL; re-run the loader (`force` on `/updates`) to fill them in. All repository methods take a `context.Context` first (handlers pass `r.Context()`).

**HTTP layer (`cmd/plot/main.go`, `internal/handlers/`).** Routes are registered in `newRouter` in `main.go` (tested in `cmd/plot/main_test.go` without a DB); each handler is a method on `Controller` (one file per route in `internal/handlers/`). `Controller` depends on the consumer-side `handlers.Repository` interface. State-changing routes (`DELETE /api/companies`, `POST`/`DELETE /api/company-note`, `PUT`/`DELETE /api/manual-financials`, `POST /api/fetch`) sit in a group behind `handlers.RequireBasicAuth` (only when `AUTH_USER`/`AUTH_PASSWORD` are set; the browser shows its native login dialog) and `handlers.RequireJSONBody` (always; a body must be `application/json`, which forces a CORS preflight and blocks cross-site form CSRF). Any new mutating route belongs in that group. `POST /api/import-manual` is the multipart exception: the same auth, no JSON-body requirement. **Pages and design system.** `/` is the screener (home), `/compare` the comparison page (`?companies=A,B` preselects), `/company/{name}` the company card, `/updates` the run log; `/screener` redirects to `/`. Every page shares `templates/layout.html` (blocks `head`, `topbar`, `footer`, data `pageMeta{Title, Active}`) and the embedded `static/` (`financialanalyzer.StaticFS`): `app.css` (design tokens for light and dark under `:root[data-theme]`, components), `app.js` (`window.FA`: theme switching with a `fa:themechange` event, the `/`/Ctrl+K company palette, the comparison tray kept in `localStorage` under `compare`, at most 8 companies = the chart palette, plus `FA.fmt` Russian number formatting) and the fonts (Golos Text, Literata; OFL). Template pages are parsed with `parsePage` (layout + page, func `asset`); the dashboard is written with `fmt` and pulls the layout blocks through `writeLayout`. `StaticHandler` serves `/static/` with content-hash versions (`assetURL` → `?v=`; a matching version is cached immutable, directory listings are 404). The theme lives client-side (`localStorage` `theme`, else the system preference) — pages no longer take `?theme=`; framed `/chart/{metric}` pages (go-echarts + a data table, `?theme=dark|light` normalized, `?companies=A,B,C`) get it from the framing page, link `app.css` and use the validated categorical palette (`chartPaletteFor`). Templates are embedded: edits need a rebuild/restart. **The UI is in Russian**: templates, chart/dashboard pages, and the user-facing strings from `analytics` (`SourceLabel`/`SourceNote`, anomaly messages, the "(устарело)" label) — keep new UI text Russian; JSON API errors and logs stay English. Money values (stored in billions of RUB) render as `млрд`/`трлн` (`humanFormat` and the chart tooltip); the chart CSV export uses `;` + UTF-8 BOM for Russian Excel.

**Adding a metric** requires changes in several places that must stay in sync: `models.QuarterData` (`*float64` field + `IsEmpty`), `rawValue` in `analytics/analytics.go`, a migration to add the column, the `SaveQuarterData` upsert, the `indexMetricGroups` list in `handlers/index.go` (the compare page) and, when the company card should chart it, `dashboardChartMetrics` in `handlers/dashboard.go`, and `formatMetricName`/`getMetricUnit`/`getTooltipFormatter` in `handlers/chart.go`. A reported (non-market) metric that can come from an annual report also belongs in the manual-entry path: a `manual_financials` column, `models.ManualFinancials` (+ `HasFundamentals`), `ApplyManual`, the repository's manual SQL, and `manualFields` in `handlers/dashboard_manual.go`.

**Primary-source fetch (`internal/scraper/girbo/`, `internal/scraper/moex/`, `internal/fetcher/`).** Free replacement for the removed smart-lab scraper (smart-lab became paywalled), sourcing `QuarterData` fields from primary data:

- `girbo` pulls annual RSBU statements from ГИР БО (`bo.nalog.gov.ru`). Flow: `SearchByINN` (`/advanced-search/organizations/search?query={inn}` — note the API wraps the matched value in `<strong>` tags, which `parseSearch` strips) → `ListReports` (`/nbo/organizations/{id}/bfo` returns every year with a real report `id`; the `publication` field is a status code, not an id) → details (`/nbo/bfo/{reportID}/details` → `financialResult.current2110` revenue, `current2400` net profit, `balance.current1300` equity, `current1410+current1510` borrowings, `current1250` cash, `financialResult.current2200` profit from sales (the EBIT proxy), `fundsMovement.current4100` operating cash flow (signed), `current4221` capex (filed as a positive outflow; taken as `|x|`)). Source is in **thousands of RUB**, converted to **billions**. RSBU forms omit zero lines, so inside a **filed** section — the balance with its total `1600`, the cash-flow statement with `4100` — a missing borrowing/cash/capex line is a reported **0** (`zeroIf`); without the total the section counts as absent and the lines stay nil. Revenue/net profit/2200 keep plain nil-if-absent.
- `moex` reconstructs market cap from MOEX ISS as `CLOSE × shares` (no historical-cap endpoint exists): year-end `CLOSE` (and its trade date) from the EOD history endpoint, shares = current `ISSUESIZE` (`/iss/securities/{SECID}.json`) with every **split** whose first post-split session (`tradedate`) is after the close undone (`SharesAt`/`SharesBefore`: `shares × before/after`). Splits come from `/iss/statistics/engines/stock/splits/{SECID}` (real list, e.g. T 1:10 on 2026-04-17, VTBR 5000:1 on 2024-07-15) merged with `Client.ExtraSplits` — the bundled **`share_splits.txt`** (`financialanalyzer.SplitRegistry`, `SECID TRADEDATE BEFORE AFTER`, per secid) for splits MOEX omits (BELU 1:8 on 2024-08-22 is missing from its list). A registry row within 31 days of a split MOEX lists is treated as the same event, skipped and warned about (never applied twice); splits dated after today are ignored. A close without a trade date, or a failed splits lookup (cached per client), makes a historical cap unavailable rather than unadjusted — under `force` the stored cap is then left as it was — while `LatestQuote` falls back to the current ISSUESIZE with a warning. After the pipelines fetch checks each ticker's **stored** history (so incremental runs see the pair too, banks included) and warns when year-end caps jump by 2× or more between consecutive years (`analytics.CapJumps`) — the signature of an unrecorded split, an extra issue or a buyback; add a registry row. The later year is marked on the capitalization chart the same way a data-quality anomaly is, and the Monday Telegram note repeats the warning. Additional issues/buybacks are not tracked, so caps across them stay approximate. A jump of 2× or more (`analytics.CapJumps`) cuts the P/E, P/B and yield history band at the later year (`BandWindow`) until a review says the move is a market price (`cap_reviews`, `POST /api/cap-reviews`: split, issue, buyback, error, price). Error drops the later year and keeps the earlier ones; price keeps both. Reviewed jumps leave the Monday warning. `/updates` lists the jumps and the registry companies whose latest stored year is still RSBU only (`RSBUOnlyLatest`). A **renamed** security keeps its old history under the old secid (TCSG -> T in 2024): the bundled **`ticker_renames.txt`** (`financialanalyzer.RenameRegistry`, `SECID OLD_SECID...`, same ISIN only) fills `Client.Predecessors`, and `CapitalizationAt` falls back to them for a year with no December close under the current secid, priced on the old secid's own frozen ISSUESIZE and splits. Existing rows get corrected caps and P/E only with `force`. Returns billions of RUB. `LatestQuote` returns the last close in the 14 days before now (same EOD history endpoint, so it is the last completed session, not intraday) and the cap it implies. `ISSUESIZE` is cached per `Client` (clients are per worker, not concurrency-safe); `Client.BaseURL` is overridable for httptest. **MOEX has no free dividends API**: `/iss/securities/{SECID}/dividends` now silently returns the security description, and `/iss/cci/corp-actions/dividends` is subscribers-only — dividends are entered with the annual IFRS figures (the company card or `POST /api/import-manual`).
- `fetcher` (`girbo.go`) joins them per `(ticker, year)`, stores `equity` (line 1300), and computes `PE = cap/net_profit`, `ROE = net_profit/equity*100`.

Derived valuation metrics (`analytics.DerivedSeries`): **`pb` = capitalization / equity**, **`div_yield` = dividends / capitalization × 100** (the year's dividends over the year-end cap). Both inputs are point-in-time (not flows), living on the Q4 row; P/B is NaN for non-positive equity, and `CheckRow` flags negative equity (concerning equity/P/B/ROE). The dashboard takes P/B and yield from the latest period that has them and shows that period under the KPI (`Snapshot.PBLabel`/`DivYieldLabel`) — for banks the latest row is usually a Q1-Q3 without market cap (it has equity, so the current-quote P/B in `BuildCurrent` is fresh, but the stored P/B comes from Q4). **Backfill:** a normal fetch skips periods already stored. `POST /api/fetch` with `backfill: true` (the «Дозаполнить пустые колонки» button on `/updates`) re-downloads only RSBU years whose equity, debt, cash, operating profit, operating cash flow or capex is still NULL, and bank quarters whose equity is still NULL; complete periods and CSV rows are left alone. `force` still re-fetches everything. Payout (`payout`, dividends / net profit) is computed only on annual RSBU and manual rows, so a bank Q4 (one quarter) and a CSV quarter stay out. Dividend CAGR (`dividends_cagr3`, `dividends_cagr5`) uses the annual dividend series. Cash-flow metrics: **`net_debt` = debt − cash**, **`ev` = capitalization + net_debt** (both point-in-time), **`operating_margin` = operating_profit / revenue × 100**, **`ev_ebit` = ev / operating_profit**, **`fcf` = operating_cash_flow − capex** (a flow), **`p_fcf` = capitalization / fcf**. On the quarterly base `ev_ebit`/`p_fcf` pair the period's EV/cap with **TTM** flows (`pickFlow`, like `debt_ebitda`); a non-positive EBIT or FCF, or a non-positive EV (cash above cap + debt), gives NaN (a negative multiple would sort as "cheapest"; the `ev`/`net_debt` charts themselves may go negative). `Snapshot` carries NetDebt/EVEBIT/PFCF (with their period labels), TTM FCF and operating margin; `BuildCurrent` prices EV/EBIT (quote cap + latest net debt, both within `MaxFundamentalAge`) and P/FCF at the quote; a too-old input withholds them and says so in `EBITLabel`/`FCFLabel` ("…, чистый долг на 2023-Q4 (устарело)") **without** setting `Current.Stale`, which still means only that P/E, P/B or yield was withheld; the screener shows `ev_ebit`, `p_fcf`, `operating_margin`. Holding-company anomalies (`holdingMetrics`) also concern operating_profit and operating_cash_flow, so these multiples are flagged for holdings. Banks have none of these lines. **Limitation:** net debt subtracts two stocks that merge column by column, a CSV row carrying only `Долг` still merges into an RSBU Q4 row without changing its `source`, but `debt_source` becomes `csv` while `cash_source` stays `rsbu`. When the two columns are different kinds (group `csv`/`manual`/`smartlab` versus standalone `rsbu`/`cbr_102`), that period's `net_debt`, `ev`, `ev_ebit` and `p_fcf` are NaN — including the current-quote EV/EBIT and P/FCF when they rest on a mixed period. An empty column source falls back to the row source, and migration 000010 backfilled both from it, so a mix already stored before the migration is not detected. `combine` still refuses a net debt built from two quarters of different kinds. Existing RSBU rows get the new columns (and debt 0 for borrowing-free filers) only with `force`.

**Current valuation (`market_quotes`, `analytics.BuildCurrent`).** One row per company (latest close, cap = close × current ISSUESIZE, trade date), written by every fetch run for companies that already have financial rows; `DeleteCompany` removes it in the same transaction. `BuildCurrent` values the quote against the latest **TTM net profit** (P/E; NaN for a loss, label kept), latest positive equity (P/B) and latest dividends (yield), each with the period it came from; a fundamental whose period ended more than `MaxFundamentalAge` (18 months) before the quote gives NaN and a "(устарело)" label (`Current.Stale`). A quote older than `QuoteMaxAge` (30 days, `QuoteIsFresh`) is ignored everywhere — the dashboard then shows a "слишком старая" note, the screener falls back to stored figures; `Controller.now` is the clock (tests pin it). Every run quotes the requested tickers; a full run (no ticker/bank list) also quotes every company already in the DB, including CSV-only ones. The dashboard shows a "Текущая оценка" block for a fresh quote.

**TTM/annual rules (`analytics`).** A TTM flow sums **four consecutive quarters** only (`quarterSeq`); an RSBU or manual Q4 row (`isAnnualFigure`: source `rsbu` or `manual`, quarter Q4) is itself the TTM/annual value (ГИР БО is annual-only; summing four such rows used to add four years). YoY and CAGR look up the same period N calendar years back by `Point.Index` (`yearsBack`, exported as `YearAgo` for the dashboard sparklines), not N positions back, so gaps never pair the wrong periods. `Point.Standalone` marks RSBU/CBR (legal-entity) figures: a TTM window or annual sum must be all one kind, and YoY/CAGR/`YearAgo` never compare group with standalone figures (e.g. CSV IFRS history followed by RSBU years). `Snapshot` takes stock figures (cap, debt, P/E, ROE, P/B, yield) from the latest period that reports them and names it (`CapLabel`, … — shown on the dashboard when it differs from the latest period). Unlike `BuildCurrent`, the snapshot has **no age bound**: a company whose data stopped years ago still shows and scores on its last figures (the labels say how old they are).

**Screener (`/`, `/api/screener`, `analytics.BuildScreenerRow`).** One row per company: valuation (cap, P/E, P/B, yield) at the latest fresh quote ("рынок" on the page, with `earnings_period`/`stale`), else the latest stored period; a loss gives a null P/E on both paths; plus ROE, margins, leverage, growth, score, data-quality flag count, sources/comparability. JSON uses null for unknown. **Relative valuation (`analytics/valuation.go`).** For `BandMetrics` (P/E, P/B, dividend yield) the screener row carries `*_hist_pct` — `HistoricalBand`: the percentile of the row's valuation (live quote or stored) among the company's own periods over the `BandYears` (10) years up to the latest qualifying one, loss P/E excluded, at least `MinBandPoints` (3); ties count half. For P/E and P/B only periods of the kind (standalone vs group, as for YoY) of the figure the value **rests on** count: `ScreenerRow.Basis` (not in JSON) holds per metric the period behind it — at a quote the TTM earnings / equity / dividends point (`Current.EarningsPoint`…), else the stored multiple's (`Snapshot.PEPoint`…) — since the latest stored P/E can be a CSV quarter while the quote is priced on RSBU earnings. The yield band ignores the kind (a dividends-only CSV write leaves an RSBU row standalone). The bands are computed once and carried on the row (`Bands`, not in JSON). `*_sector` medians (`ApplySectorMedians(rows, now)`, run by `buildScreener` over all rows): the median over the **other** companies of the category whose value is current (`CurrentAt`: priced at a fresh quote, or a stored period at most `MaxFundamentalAge` before now) and, for P/E/P/B, of the row's own kind; at least `MinSectorPeers` (2); `*_sector_peers` counts them. A row whose own value is missing or too old gets no median (the dashboard says "оценка устарела"). Low = cheap for P/E/P/B, high for yield (`HigherIsCheaper`). The dashboard's "Оценка относительно истории и сектора" block (`handlers/dashboard_valuation.go`) uses the company's screener row (so it shows the same figures as the screener, and it loads every company's history), naming each value's basis period; a failed peer load hides only the sector column, and a company missing from the batch read is built separately and joined to the peers. The screener page adds "P/E к сектору" and "P/E: перцентиль истории" columns, P/B/yield tooltips and a median row over the shown rows (a median of the shown values that uses the same rules as `*_sector`: the value is current (`CurrentAt`) and, for P/E and P/B, of one reporting kind (the kind with more shown rows). A bank's composite score is null in that column (`ScreenerRow.Score`) so it does not sort with industrials; the card still shows the bank scale). The page (`templates/screener.html`, embedded) sorts and filters client-side (search, category, P/E/P/B/yield/ROE ranges, comparable-only, no-flags) with ready-made selections (cheaper than history / sector, dividend, reliable data), user-saved selections and optional columns (both in `localStorage`), filter chips, a summary drawer per row and compare checkboxes feeding the tray. The company card (`handlers/dashboard.go`) opens with a valuation verdict built from the same row (`valuationVerdict`) and draws the bands as rulers (`renderValuationRulers`) above the detailed table.

Inherent limitations (documented in package docs): ГИР БО is **annual-only** (rows are stored at `Q4`; they count as the annual/TTM value — see "TTM/annual rules") and **unconsolidated RSBU, not IFRS** (parent-entity figures diverge from group numbers, so P/E/ROE won't match smart-lab; ROE in particular runs high). **Banks are absent** (they report to the Central Bank; see "Bank fetch"). **EBITDA is left empty.** The INN comes from the bundled registry (`fetch_tickers.txt`, embedded via `financialanalyzer.TickerRegistry`; see "Ticker registry"). An explicitly requested ticker missing from it (and given without an INN) is resolved through MOEX ISS (`fillMissingINN` → `moex.EmitterOf`: description ISIN → `/iss/securities?q=ISIN` `emitent_inn`); a bank ticker is not looked up (hint: request it as a bank), and an unresolvable one lands in `Summary.Failed` (run `partial`) instead of being dropped; an INN already registered under another ticker (e.g. `SNGSP` next to `SNGS`) is warned about (it would become a second company). A quotes-only run makes no lookups (quotes need only the ticker). Runs over stored companies never call the lookup, so an ISS outage cannot fail the schedule. The fetcher runs tickers concurrently (`concurrency` on `POST /api/fetch`, each worker with its own rate-limited clients) and skips `(company, year)` periods already in the DB unless `force` is set — `girbo.FetchAnnual`'s `skip` callback avoids even downloading their details. A failed report year does not discard the rest of the ticker: `FetchAnnual` returns the parsed years with a `*girbo.PartialError`, and the ticker is saved but counted as failed. Fixtures in each package's `testdata/` are the regression tests; refresh by re-curling if the APIs change.

**Ticker registry (`fetch_tickers.txt`).** The bundled list (`financialanalyzer.TickerRegistry`) is what «весь реестр» fetches: `TICKER INN CATEGORY`, `#` comments. It is a reviewed snapshot edited by hand and embedded at build time. Banks stay in `bank_tickers.txt`. A ticker requested without an INN is still resolved through MOEX ISS (`fillMissingINN`).

**Bank fetch (`internal/scraper/cbr/`, `internal/fetcher/banks.go`).** Banks report to the Central Bank, not ГИР БО, so they have their own pipeline. The CBR publishes the whole banking sector's form 102 ("Отчёт о финансовых результатах") and form 101 (turnover sheet of balance accounts) per period as RAR archives of DBF tables at `https://www.cbr.ru/vfs/credit/forms/{102,101}-YYYYMMDD.rar` (`.zip` before 2009; the page only lists old archives but recent dates resolve directly). Archives are decoded with `github.com/nwaples/rardecode/v2` (RAR5); a tiny hand-rolled `parseDBF` reads the dBASE III header + fixed-width records (field names are cut at their NUL terminator: pre-2022 archives leave junk after it); only ASCII columns are read, except form 101's PLAN, compared as the raw cp866 byte (`"\x80"` = plan "А"). DBF values are **thousands of RUB**, converted to billions. The archive date is the first day *after* the period (`YYYY0401`=Q1, `0701`=H1, `1001`=9M, next-year `0101`=full year — see `cbr.ArchiveDate`).
- `cbr.Client.FetchPeriod(archiveDate)` (form 102, `*_P1.dbf`, columns REGN/CODE/SIM_ITOGO; **YTD cumulative**) returns `REGN -> cbr.Form102{NetProfit, Revenue}`. Net profit after tax is **CODE 61101** (61102 is the loss counterpart); banks without it are omitted. **Revenue is a proxy**: net interest income = Part 1 sections 1-4, 6 (`11000`,`12000`,`13000`,`14000`,`16000`) minus Part 3 sections 1-6 (`31000`…`36000`), provisions excluded, plus gross fee income `27000` (fee expense has no separate section total, so it is not netted). This layout holds since the 2016 chart of accounts (section names checked identical in the 2017–2026 archives' `SPRAV1.dbf`); older archives have no 61101 and yield nothing.
- `cbr.Client.FetchEquity(archiveDate)` (form 101, `*B1.dbf`, columns REGN/PLAN/NUM_SC/A_P/IITG; point-in-time) returns balance-sheet **equity**: outgoing balances of plan "А" capital accounts `1xx` and financial-result accounts `706`-`708`, passive (`A_P`=2) positive, active (1) negative. Archives up to 2021 list 5-digit second-order accounts, later ones 3-digit aggregates; a 3-digit row wins over the 5-digit rows under it.
- `fetchBanks` downloads a year's four 102 archives once, **differences consecutive cumulatives** into single-quarter net profit and revenue, stores each quarter-end's form 101 equity on every row (so the current P/B uses the latest quarter), and attaches year-end market cap + annual P/E (cap / full-year profit) + ROE (full-year profit / year-end equity × 100) to the Q4 row. `bankRows` takes the cap lookup as a function, so it is unit-tested without MOEX. A quarter whose form 101 is still unavailable within `equityGrace` (90 days) of its archive date is **not written**, so the next run retries it instead of storing it without equity forever (`equityPending`); older quarters are written without equity. Only quarters with form 102 data that some requested bank still lacks download form 101. ROE uses year-end (not average) equity, which includes the year's own profit (account 706). Existing rows get revenue/equity only with `force` — until then old Q4 rows still hold the former form 123 regulatory capital as `equity` and ROE.

Banks are keyed by CBR **REGN** (from `bank_tickers.txt`, embedded via `financialanalyzer.BankRegistry`); the ticker doubles as the MOEX secid for cap. EBITDA/debt have no meaningful bank equivalent and stay empty. Fixtures `internal/scraper/cbr/testdata/102-20240101.rar` (Sberbank REGN 1481: net profit 1493.1 bln = published RSBU; revenue 3414.5 = NII 2414.7 + fees 999.8) and `101-20240101.rar` (Sberbank equity 6340.7 bln) are the regression tests; synthetic in-test DBFs cover the parsers directly.

**Scheduled refresh and run log (`internal/fetcher`, `internal/scheduler`, `fetch_runs`, `/updates`).** `fetcher.Run(ctx, repo, Request, logger)` is the one entry to both pipelines + quotes + the cap-jump check; `Request`'s zero value refreshes every stored company. It returns a `Summary` per company: **updated**, **up to date** or **failed**, decided by `fetcher.classify` — any source error (a `girbo.PartialError`, a CBR download error other than `ErrNotPublished`) or save error makes a company failed even if some rows were written; "no new rows" is up to date only if the source knows the company (ГИР БО lists a year we already store, or the bank is in this run's form 102 archives, or nothing needed downloading). `fetcher.RunRecorded` wraps a run in a `fetch_runs` row (`kind` quotes|financials, `trigger` cli|schedule|catchup, `full_scope` = no explicit list, `status` running|ok|partial|failed|canceled|abandoned); the outcome is written on a context detached from the canceled run ctx. Runs from both binaries are **serialized** by a Postgres session-level advisory lock (`Repository.LockFetch`, on a connection taken out of the pool for the run with `lock_timeout`/`statement_timeout` set to 0 and **never returned to the pool** — closed via `driver.ErrBadConn` — so a re-entrant lock can never leak into it; a success always means the lock is held; needs a real session, not PgBouncer transaction pooling): a second run waits (logged), a cancel during the wait returns without recording a run, and any other lock error **fails the run without running it** (reported, not recorded). Under the lock every other `running` row is dead, so the run marks them all abandoned (`StaleRunAge`, 12 h, is left only to the scheduler's startup sweep). `fetcher.RunOptions.StillNeeded` is checked once the lock is held: the scheduler's catch-up passes `missed`, so a catch-up that waited for a manual full run it no longer needs is skipped (`ErrNotNeeded`); a regular slot firing during a manual run still runs after it. A `failed` or `partial` run (including a lock failure) is reported through `RunOptions.Notifier` (`notify.Notifier`; `internal/notify` Telegram client, `Application.Notifier`, nil when `TELEGRAM_*` are unset) after the lock is released, best-effort; the message is Russian plain text and, unlike `/updates`, quotes the raw error (the chat is the operator's), and notify errors never contain the bot token. On Monday after the quotes slot, `sendCheapList` sends one more note (`analytics.MondayMessage`): the cheap list, portfolio names whose P/E entered an outer quartile of their ten-year band since the previous note (`portfolio_bands`), quotes older than 30 days, cap jumps of 2× or more, and IFRS years queued in `digest_events` when a pull wrote a year that was not stored. The queued years and the remembered bands are updated only after that note is delivered. Run kind/trigger/status Russian labels live in `models` (`RunKindLabel`, …) for both the page and the message. `partial` = some company failed, or no quote was saved at all (CSV-only names failing their quote are routine and do not count). An empty DB (`fetcher.ErrNoCompanies`) is `ok` — nothing to refresh. `internal/scheduler` (started by `cmd/plot` when `SCHEDULER_ENABLED`) runs jobs sequentially in one goroutine at Moscow wall-clock slots (`Spec`: daily `HH:MM` or weekly `DAY HH:MM`; `models.Moscow` is a fixed UTC+3 zone). On startup it marks its own leftover `running` rows abandoned, waits 30 s, then catches up each job whose latest slot (`Spec.Prev`) has no completed (ok/partial) full-scope run since — financials first, since a financials run satisfies the quotes job too — and recomputes next slots so a caught-up slot never fires twice. `cmd/plot` cancels the scheduler and waits for it before closing the DB pool. A manual fetch from `/updates` started during a scheduled run waits for it (and vice versa); `/updates` shows the waiting scheduled job as running. `/updates` (Russian page) and `/api/fetch-runs` show the timetable, quote freshness and the latest 50 runs; they are unauthenticated, so `FetchRun.Error` (the raw error chain) is never served (`json:"-"`, the page only says that the run failed) and `Scope` holds only a list file's base name. Run kinds, triggers and `ScheduledJob` live in `models`, so `handlers` does not import the fetcher.

**Manual entries (`manual_financials`, `models.ApplyManual`, `/api/manual-financials`, dashboard block).** Figures typed in on the dashboard or uploaded as a batch on `/updates` (`POST /api/import-manual`: semicolon CSV, one company-year per row, the same columns as the form; a row replaces that year's manual entry) — usually the group's IFRS annual report — one row per company-**year** (annual only), billions of RUB, nil = not entered. They live in their own table, so no loader (fetch or the scheduler) can overwrite them, and are overlaid when the history is read (`GetCompanyHistory`/`GetCompaniesHistory` → `ApplyManual`; `fetchedHistory` is the raw read, which `ExistingPeriods`-style fetch logic never sees through). Rules: an entry with any reported figure besides dividends (`HasFundamentals`) **replaces the year's Q4 row wholesale** — fetched flows and balance-sheet figures are dropped (never mix a parent's RSBU with group IFRS, nor a CSV quarter with an annual figure), capitalization (market data) and unentered dividends stay, P/E and ROE are recomputed from the entered profit/equity, source becomes `manual` (annual like RSBU, comparable like CSV); a dividends-only entry just sets dividends. A year without a fetched Q4 row gets a new one (a dividends-only one keeps the company's usual source). Next to single-quarter data (CSV, CBR) a manual annual Q4 needs two guards: the replaced quarter is kept on the row as `QuarterData.Quarterly` so the TTM windows of Y+1 Q1–Q3 still sum four quarters, and quarterly-series points carry `Point.Annual` so YoY/CAGR/`YearAgo` (`comparablePoints`) never compare a year with a quarter. Dividends also have their own annual file (`POST /api/import-dividends`, columns `компания;год;дивиденды`): it sets only that column, so an IFRS row for the year is not cleared. When no period reports dividends, the company card says «дивиденды не введены» next to the empty yield. Deleting the entry restores the fetched figures; `DeleteCompany` removes entries too. `PUT` replaces the whole entry (omitted = cleared), rejects unknown fields, empty entries, years outside 1990..current, negative revenue/capex/debt/cash/dividends, values ≥ 1e13 (the column limit; usually thousands typed into a billions field), trailing JSON, and companies with no fetched/imported rows (404; checked inside the INSERT so a concurrent `DeleteCompany` cannot leave an orphan). The dashboard form accepts Russian number formatting ("1 234,5"). Dashboard values reach inline scripts only through `jsonForScript` (json.Marshal escapes `<`, `>`, `&`), and the chart page normalizes its `theme` query parameter to light/dark before echoing it.

**Data quality (`internal/analytics/quality.go`).** `CheckRow`/`CheckHistory` flag suspicious figures: negative equity, P/E > 200 (negative P/E = a loss, not flagged), |ROE| > 100%, revenue < 1% of market cap, and net profit > revenue (the signature of a holding company's standalone RSBU, where income is subsidiaries' dividends; skipped for `cbr_102` rows, whose revenue is only a net-interest + fee proxy). Bank rows carry revenue, so their net margin, revenue growth and score parts are no longer NaN — bank scores are not comparable with industrials' and are omitted from the screener score column. Each `Anomaly` lists the raw metrics it concerns; `Concerns`/`AnomaliesByLabel` map it onto derived metrics and chart labels. `IsComparable` treats `rsbu`/`cbr_102` as not comparable across companies; `csv`/`smartlab` and legacy NULL sources are neutral. `source` is row-level, last writer wins (see `models.QuarterData`). The chart page shows a Source column, highlights flagged cells (hover = reason) and draws flagged points as triangles; the dashboard shows a "Data quality" block. Note: code inside go-echarts `opts.FuncOpts` is JSON-encoded and injected verbatim, so it must not contain double quotes or backslashes — use `jsStringMap`/`jsString` in `handlers/chart.go` for dynamic strings.

**HTTP retries (`internal/scraper/httpx/`).** All scraper clients (girbo, moex, cbr) fetch through `httpx.Get`, which retries transport errors, 429 and 5xx with exponential backoff (`httpx.DefaultPolicy`: 3 attempts, 1s/2s, honours `Retry-After`, and gives up instead of retrying early when it exceeds `MaxDelay`); clients reset their rate-limit clock after the last attempt; other statuses return an `*httpx.StatusError` immediately (cbr maps 404 to `ErrNotPublished`). Each client's `Retry` field overrides the policy (tests use millisecond delays). Rate limiting (`Delay`) stays per client.

**Migrations.** Standard `golang-migrate` numbered up/down files in `migrations/`. Migrations run automatically on every startup of any binary; new migrations take effect with no separate step.
