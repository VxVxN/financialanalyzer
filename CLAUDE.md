# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Go application that ingests Russian-language quarterly financial data and serves an interactive web UI for cross-company metric comparison. Three binaries share `internal/`:

- `cmd/import` — one-shot CSV ingestion (set `CSV_PATH`, run, exits).
- `cmd/fetch` — builds financials from free primary sources: annual RSBU from ГИР БО + year-end market cap from MOEX ISS, computing P/E and ROE itself (see "Primary-source fetch" below); listed banks come from the CBR's quarterly form 102/101 archives (see "Bank fetch"). A thin `FETCH_*` env → `fetcher.Request` wrapper: the pipelines live in `internal/fetcher`.
- `cmd/plot` — HTTP server (default `:8088`) that renders the UI and chart pages, and (with `SCHEDULER_ENABLED=1`) runs the fetch pipelines on a timetable (see "Scheduled refresh").

All three call `database.RunMigrations` on startup, so any entrypoint will bring the schema up to date.

## Commands

```bash
# Run web server (reads env vars, see config.go for defaults)
go run ./cmd/plot

# Import a CSV file (filename encodes company + category, see "CSV format" below)
CSV_PATH=/path/to/SBER_banks.csv go run ./cmd/import

# Fetch from free primary sources (ГИР БО + MOEX ISS). Ticker INN/category are
# resolved from the bundled registry (fetch_tickers.txt), so a request can be
# just the ticker; INN/category may still be given explicitly to override.
go run ./cmd/fetch                                    # companies already in the DB
FETCH_ALL=1 go run ./cmd/fetch                        # every ticker in both registries
FETCH_TICKERS="OZON,X5:retail" go run ./cmd/fetch    # registry-resolved
FETCH_TICKERS="MGNT:2309085638:retail" go run ./cmd/fetch  # full explicit form
FETCH_TICKERS_FILE=/path/to/list.txt go run ./cmd/fetch
# Knobs: FETCH_CONCURRENCY (default 3, parallel tickers), FETCH_FORCE (re-fetch
# periods already in the DB instead of skipping them). Every run also refreshes
# the latest exchange close (market_quotes) of the requested tickers;
# FETCH_QUOTES_ONLY=1 does only that (fast, for current P/E):
FETCH_QUOTES_ONLY=1 go run ./cmd/fetch

# Banks come from the CBR form 102/101 archives (separate pipeline, separate
# registry bank_tickers.txt mapping TICKER->REGN). Runs by default alongside the
# ГИР БО list; request a subset / limit the year range explicitly:
FETCH_BANKS="T" FETCH_BANK_FROM_YEAR=2009 go run ./cmd/fetch
# With no FETCH_* list set, both pipelines refresh only the companies already in
# the DB that appear in their registry (stored category kept); FETCH_ALL=1 runs
# the full bundled registries instead. Requesting one kind (FETCH_TICKERS or
# FETCH_BANKS) suppresses the other; new companies are added by naming them.

# Let the server refresh the stored companies itself (quotes daily 07:00,
# financials Sundays 05:00, Moscow time; "off" disables a job):
SCHEDULER_ENABLED=1 SCHEDULE_QUOTES=07:00 SCHEDULE_FINANCIALS="sun 05:00" go run ./cmd/plot

# Build
go build ./...

# Tests. The repository integration tests in internal/database skip unless
# TEST_DATABASE_DSN points at a THROWAWAY Postgres (they truncate its tables);
# CI runs them against a postgres service container.
go test ./...
TEST_DATABASE_DSN="host=127.0.0.1 port=55432 user=test dbname=postgres sslmode=disable" go test ./internal/database/
```

Migrations and templates are embedded (`embed.go`: `financialanalyzer.MigrationsFS` / `TemplatesFS`), so binaries run from any working directory.

Config is env-var only (`internal/config/config.go`): `PORT`, `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_SSLMODE`, `CSV_PATH`, `AUTH_USER`, `AUTH_PASSWORD`, `SCHEDULER_ENABLED`, `SCHEDULE_QUOTES`, `SCHEDULE_FINANCIALS`. Defaults target a local Postgres (`localhost:5432`, user `postgres`, password `password`, db `postgres`). `AUTH_USER`/`AUTH_PASSWORD` must be set together (`Validate` rejects one without the other).

## Architecture

**Data model.** `company_financials` is the single fact table, keyed by `(year, quarter, company)` with a `category` column and one column per metric (capitalization, revenue, net_profit, ebitda, debt, pe, roe, equity, dividends, cash, operating_profit, operating_cash_flow, capex). The flows are revenue, net_profit, ebitda, operating_profit, operating_cash_flow and capex (`analytics.IsFlow`; the upsert's annual/quarterly flip logic covers all six); the rest are point-in-time. Metric fields in `models.QuarterData` are `*float64`: **nil = not reported (NULL), non-nil zero = a real zero** (e.g. a debt-free company). Loaders set only what they know — the zero value is safe, because nil never overwrites a stored value. Build values with `models.Float(v)`; analytics reads them via `models.ValueOrNaN` (NaN is its missing-value convention, so a reported 0 stays 0 in series and snapshots). A `source` column (`models.Source*`: `rsbu`, `cbr_102`, `csv`; `smartlab` survives only on legacy rows from the removed scraper; NULL for older rows) records which pipeline wrote the row; every loader must set `QuarterData.Source`, and the upsert keeps the existing source when the new one is empty. `company_notes` holds free-text notes keyed by company. `source` also tells what the **flow** metrics mean (an RSBU Q4 row = the whole year, CSV/CBR rows = one quarter), so the upsert only lets a write that carries flows (any of the six above) change it — a CSV row with only dividends never relabels annual RSBU figures — and when incoming flows flip a **Q4 row between annual (rsbu) and single-quarter** meaning, the old flows and the P/E/ROE derived from them are replaced rather than merged (no row mixes annual and quarterly figures); every other source change (csv/smartlab/legacy NULL — all quarterly) merges, and stock metrics always merge. `SaveQuarterData` does an upsert that uses `COALESCE(EXCLUDED.x, existing.x)` so a row imported with only some metrics filled in won't wipe previously-imported metrics for the same quarter (a consequence: a wrong stored value can be corrected, but not cleared back to NULL, by re-importing). Rows written before the pointer change stored reported zeros as NULL; re-run the loader (`FETCH_FORCE=1` for `cmd/fetch`) to fill them in. All repository methods take a `context.Context` first (handlers pass `r.Context()`).

**CSV ingestion (`internal/parser/csv_parser.go`).** Input is semicolon-delimited with the header row containing quarter labels like `2023-Q1`; `LTM` columns are skipped. Metric rows are matched in two ways:
- Exact prefix match against a handler map (`Капитализация`, `Выручка`, `EBITDA`, `ROE`).
- Substring match for "special" metrics with disambiguation rules (`P/E`, `Долг` but not `Чистый долг` or a ratio such as `Долг/EBITDA`, `Чистая прибыль` but not the `н/с` variant), and prefix matches for the cash-flow rows `Операционная прибыль`, `Наличность`, `Операционный денежный поток`, `CAPEX` (stored as a positive outflow). A row label containing `/` or `%` is a ratio and never fills an amount column (`isRatioRow`).

A row starting with `Дивиденды` (and containing no `/`, `%` or `акци`) holds the **year's total dividends in billions**; only its Q4 columns are read, and there `0` is a real "no payout" (the placeholder rule doesn't apply). Per-share (`Дивиденд, руб/акцию`), payout (`Дивиденды/прибыль, %`) and yield rows are ignored. Company name and category are parsed from the **filename**: `<COMPANY>_<CATEGORY>.csv` (split on `_`). Numeric values are normalized by stripping spaces, `%`, quotes, and converting `,` → `.`. Any value that parses to 0 is treated as **no data** (aggregator exports use 0 as a placeholder, e.g. a bank's revenue or a loss quarter's P/E) — honest zeros come only from the primary sources.

**HTTP layer (`cmd/plot/main.go`, `internal/handlers/`).** Routes are registered in `newRouter` in `main.go` (tested in `cmd/plot/main_test.go` without a DB); each handler is a method on `Controller` (one file per route in `internal/handlers/`). `Controller` depends on the consumer-side `handlers.Repository` interface. State-changing routes (`DELETE /api/companies`, `POST`/`DELETE /api/company-note`) sit in a group behind `handlers.RequireBasicAuth` (only when `AUTH_USER`/`AUTH_PASSWORD` are set; the browser shows its native login dialog) and `handlers.RequireJSONBody` (always; a body must be `application/json`, which forces a CORS preflight and blocks cross-site form CSRF). Any new mutating route belongs in that group. `/chart/{metric}` returns a self-contained HTML page (embedded CSS + go-echarts JS + a data table) and supports `?theme=dark|light` and `?companies=A,B,C`. The index page (`templates/index.html`) is loaded fresh on each request — edits don't require restart. **The UI is in Russian**: templates, chart/dashboard pages, and the user-facing strings from `analytics` (`SourceLabel`/`SourceNote`, anomaly messages, the "(устарело)" label) — keep new UI text Russian; JSON API errors and logs stay English. Money values (stored in billions of RUB) render as `млрд`/`трлн` (`humanFormat` and the chart tooltip); the chart CSV export uses `;` + UTF-8 BOM for Russian Excel.

**Adding a metric** requires changes in several places that must stay in sync: `models.QuarterData` (`*float64` field + `IsEmpty`), `rawValue` in `analytics/analytics.go`, a migration to add the column, the `SaveQuarterData` upsert, parser handlers/special-type switch in `csv_parser.go`, the `metrics` slice in `handlers/index.go`, and `formatMetricName`/`getMetricUnit`/`getTooltipFormatter` in `handlers/chart.go`.

**Primary-source fetch (`internal/scraper/girbo/`, `internal/scraper/moex/`, `internal/fetcher/`).** Free replacement for the removed smart-lab scraper (smart-lab became paywalled), sourcing `QuarterData` fields from primary data:

- `girbo` pulls annual RSBU statements from ГИР БО (`bo.nalog.gov.ru`). Flow: `SearchByINN` (`/advanced-search/organizations/search?query={inn}` — note the API wraps the matched value in `<strong>` tags, which `parseSearch` strips) → `ListReports` (`/nbo/organizations/{id}/bfo` returns every year with a real report `id`; the `publication` field is a status code, not an id) → details (`/nbo/bfo/{reportID}/details` → `financialResult.current2110` revenue, `current2400` net profit, `balance.current1300` equity, `current1410+current1510` borrowings, `current1250` cash, `financialResult.current2200` profit from sales (the EBIT proxy), `fundsMovement.current4100` operating cash flow (signed), `current4221` capex (filed as a positive outflow; taken as `|x|`)). Source is in **thousands of RUB**, converted to **billions**. RSBU forms omit zero lines, so inside a **filed** section — the balance with its total `1600`, the cash-flow statement with `4100` — a missing borrowing/cash/capex line is a reported **0** (`zeroIf`); without the total the section counts as absent and the lines stay nil. Revenue/net profit/2200 keep plain nil-if-absent.
- `moex` reconstructs market cap from MOEX ISS as `CLOSE × shares` (no historical-cap endpoint exists): year-end `CLOSE` (and its trade date) from the EOD history endpoint, shares = current `ISSUESIZE` (`/iss/securities/{SECID}.json`) with every **split** whose first post-split session (`tradedate`) is after the close undone (`SharesAt`/`SharesBefore`: `shares × before/after`). Splits come from `/iss/statistics/engines/stock/splits/{SECID}` (real list, e.g. T 1:10 on 2026-04-17, VTBR 5000:1 on 2024-07-15) merged with `Client.ExtraSplits` — the bundled **`share_splits.txt`** (`financialanalyzer.SplitRegistry`, `SECID TRADEDATE BEFORE AFTER`, per secid) for splits MOEX omits (BELU 1:8 on 2024-08-22 is missing from its list). A registry row within 31 days of a split MOEX lists is treated as the same event, skipped and warned about (never applied twice); splits dated after today are ignored. A close without a trade date, or a failed splits lookup (cached per client), makes a historical cap unavailable rather than unadjusted — under `FETCH_FORCE` the stored cap is then left as it was — while `LatestQuote` falls back to the current ISSUESIZE with a warning. After the pipelines `cmd/fetch` checks each ticker's **stored** history (so incremental runs see the pair too, banks included) and warns when year-end caps jump more than 4× between consecutive years (`capJumps`) — the signature of an unrecorded split; add a registry row. Splits of 1:2–1:4 are below that threshold. Additional issues/buybacks are not tracked, so caps across them stay approximate. A **renamed** security keeps its old history under the old secid (TCSG -> T in 2024): the bundled **`ticker_renames.txt`** (`financialanalyzer.RenameRegistry`, `SECID OLD_SECID...`, same ISIN only) fills `Client.Predecessors`, and `CapitalizationAt` falls back to them for a year with no December close under the current secid, priced on the old secid's own frozen ISSUESIZE and splits. Existing rows get corrected caps and P/E only with `FETCH_FORCE=1`. Returns billions of RUB. `LatestQuote` returns the last close in the 14 days before now (same EOD history endpoint, so it is the last completed session, not intraday) and the cap it implies. `ISSUESIZE` is cached per `Client` (clients are per worker, not concurrency-safe); `Client.BaseURL` is overridable for httptest. **MOEX has no free dividends API**: `/iss/securities/{SECID}/dividends` now silently returns the security description, and `/iss/cci/corp-actions/dividends` is subscribers-only — dividends come from CSV instead.
- `fetcher` (`girbo.go`) joins them per `(ticker, year)`, stores `equity` (line 1300), and computes `PE = cap/net_profit`, `ROE = net_profit/equity*100`.

Derived valuation metrics (`analytics.DerivedSeries`): **`pb` = capitalization / equity**, **`div_yield` = dividends / capitalization × 100** (the year's dividends over the year-end cap). Both inputs are point-in-time (not flows), living on the Q4 row; P/B is NaN for non-positive equity, and `CheckRow` flags negative equity (concerning equity/P/B/ROE). The dashboard takes P/B and yield from the latest period that has them and shows that period under the KPI (`Snapshot.PBLabel`/`DivYieldLabel`) — for banks the latest row is usually a Q1-Q3 without market cap (it has equity, so the current-quote P/B in `BuildCurrent` is fresh, but the stored P/B comes from Q4). **Backfill:** `cmd/fetch` skips periods already stored, so existing rows only get `equity` with `FETCH_FORCE=1`. Payout ratio is intentionally absent: bank Q4 rows hold single-quarter profit, so dividends / Q4 profit would be wrong for them. The CSV parser does not read equity (a `Капитал` prefix would collide with `Капитализация`). Cash-flow metrics: **`net_debt` = debt − cash**, **`ev` = capitalization + net_debt** (both point-in-time), **`operating_margin` = operating_profit / revenue × 100**, **`ev_ebit` = ev / operating_profit**, **`fcf` = operating_cash_flow − capex** (a flow), **`p_fcf` = capitalization / fcf**. On the quarterly base `ev_ebit`/`p_fcf` pair the period's EV/cap with **TTM** flows (`pickFlow`, like `debt_ebitda`); a non-positive EBIT or FCF, or a non-positive EV (cash above cap + debt), gives NaN (a negative multiple would sort as "cheapest"; the `ev`/`net_debt` charts themselves may go negative). `Snapshot` carries NetDebt/EVEBIT/PFCF (with their period labels), TTM FCF and operating margin; `BuildCurrent` prices EV/EBIT (quote cap + latest net debt, both within `MaxFundamentalAge`) and P/FCF at the quote; a too-old input withholds them and says so in `EBITLabel`/`FCFLabel` ("…, чистый долг на 2023-Q4 (устарело)") **without** setting `Current.Stale`, which still means only that P/E, P/B or yield was withheld; the screener shows `ev_ebit`, `p_fcf`, `operating_margin`. Holding-company anomalies (`holdingMetrics`) also concern operating_profit and operating_cash_flow, so these multiples are flagged for holdings. Banks have none of these lines. **Limitation:** net debt subtracts two stocks that merge column by column, so a row can pair group debt from a CSV with the parent's RSBU cash (a CSV row carrying only `Долг` merges into an RSBU Q4 row without changing its `source`); `combine`'s kind check sees one row and cannot catch it — per-column provenance would be needed. Existing RSBU rows get the new columns (and debt 0 for borrowing-free filers) only with `FETCH_FORCE=1`.

**Current valuation (`market_quotes`, `analytics.BuildCurrent`).** One row per company (latest close, cap = close × current ISSUESIZE, trade date), written by every `cmd/fetch` run for companies that already have financial rows; `DeleteCompany` removes it in the same transaction. `BuildCurrent` values the quote against the latest **TTM net profit** (P/E; NaN for a loss, label kept), latest positive equity (P/B) and latest dividends (yield), each with the period it came from; a fundamental whose period ended more than `MaxFundamentalAge` (18 months) before the quote gives NaN and a "(устарело)" label (`Current.Stale`). A quote older than `QuoteMaxAge` (30 days, `QuoteIsFresh`) is ignored everywhere — the dashboard then shows a "слишком старая" note, the screener falls back to stored figures; `Controller.now` is the clock (tests pin it). Every run quotes the requested tickers; a full run (no `FETCH_*` list) also quotes every company already in the DB, including CSV-only ones. The dashboard shows a "Текущая оценка" block for a fresh quote.

**TTM/annual rules (`analytics`).** A TTM flow sums **four consecutive quarters** only (`quarterSeq`); an RSBU Q4 row (`isAnnualFigure`: source `rsbu`, quarter Q4) is itself the TTM/annual value (ГИР БО is annual-only; summing four such rows used to add four years). YoY and CAGR look up the same period N calendar years back by `Point.Index` (`yearsBack`, exported as `YearAgo` for the dashboard sparklines), not N positions back, so gaps never pair the wrong periods. `Point.Standalone` marks RSBU/CBR (legal-entity) figures: a TTM window or annual sum must be all one kind, and YoY/CAGR/`YearAgo` never compare group with standalone figures (e.g. CSV IFRS history followed by RSBU years). `Snapshot` takes stock figures (cap, debt, P/E, ROE, P/B, yield) from the latest period that reports them and names it (`CapLabel`, … — shown on the dashboard when it differs from the latest period). Unlike `BuildCurrent`, the snapshot has **no age bound**: a company whose data stopped years ago still shows and scores on its last figures (the labels say how old they are).

**Screener (`/screener`, `/api/screener`, `analytics.BuildScreenerRow`).** One row per company: valuation (cap, P/E, P/B, yield) at the latest fresh quote ("рынок" on the page, with `earnings_period`/`stale`), else the latest stored period; a loss gives a null P/E on both paths; plus ROE, margins, leverage, growth, score, data-quality flag count, sources/comparability. JSON uses null for unknown. The page (`templates/screener.html`, embedded) sorts and filters client-side (search, category, P/E/P/B/yield/ROE ranges, comparable-only, no-flags) and shares the index page's `localStorage` theme.

Inherent limitations (documented in package docs): ГИР БО is **annual-only** (rows are stored at `Q4`; they count as the annual/TTM value — see "TTM/annual rules") and **unconsolidated RSBU, not IFRS** (parent-entity figures diverge from group numbers, so P/E/ROE won't match smart-lab; ROE in particular runs high). **Banks are absent** (they report to the Central Bank; see "Bank fetch"). **EBITDA is left empty.** Ticker↔INN is not bridged by either API, so the INN comes from the bundled registry (`fetch_tickers.txt`, embedded via `financialanalyzer.TickerRegistry`); add a row there to support a new ticker. The fetcher runs tickers concurrently (`FETCH_CONCURRENCY`, each worker with its own rate-limited clients) and skips `(company, year)` periods already in the DB unless `FETCH_FORCE` is set — `girbo.FetchAnnual`'s `skip` callback avoids even downloading their details. A failed report year does not discard the rest of the ticker: `FetchAnnual` returns the parsed years with a `*girbo.PartialError`, and the ticker is saved but counted as failed. Fixtures in each package's `testdata/` are the regression tests; refresh by re-curling if the APIs change.

**Bank fetch (`internal/scraper/cbr/`, `internal/fetcher/banks.go`).** Banks report to the Central Bank, not ГИР БО, so they have their own pipeline. The CBR publishes the whole banking sector's form 102 ("Отчёт о финансовых результатах") and form 101 (turnover sheet of balance accounts) per period as RAR archives of DBF tables at `https://www.cbr.ru/vfs/credit/forms/{102,101}-YYYYMMDD.rar` (`.zip` before 2009; the page only lists old archives but recent dates resolve directly). Archives are decoded with `github.com/nwaples/rardecode/v2` (RAR5); a tiny hand-rolled `parseDBF` reads the dBASE III header + fixed-width records (field names are cut at their NUL terminator: pre-2022 archives leave junk after it); only ASCII columns are read, except form 101's PLAN, compared as the raw cp866 byte (`"\x80"` = plan "А"). DBF values are **thousands of RUB**, converted to billions. The archive date is the first day *after* the period (`YYYY0401`=Q1, `0701`=H1, `1001`=9M, next-year `0101`=full year — see `cbr.ArchiveDate`).
- `cbr.Client.FetchPeriod(archiveDate)` (form 102, `*_P1.dbf`, columns REGN/CODE/SIM_ITOGO; **YTD cumulative**) returns `REGN -> cbr.Form102{NetProfit, Revenue}`. Net profit after tax is **CODE 61101** (61102 is the loss counterpart); banks without it are omitted. **Revenue is a proxy**: net interest income = Part 1 sections 1-4, 6 (`11000`,`12000`,`13000`,`14000`,`16000`) minus Part 3 sections 1-6 (`31000`…`36000`), provisions excluded, plus gross fee income `27000` (fee expense has no separate section total, so it is not netted). This layout holds since the 2016 chart of accounts (section names checked identical in the 2017–2026 archives' `SPRAV1.dbf`); older archives have no 61101 and yield nothing.
- `cbr.Client.FetchEquity(archiveDate)` (form 101, `*B1.dbf`, columns REGN/PLAN/NUM_SC/A_P/IITG; point-in-time) returns balance-sheet **equity**: outgoing balances of plan "А" capital accounts `1xx` and financial-result accounts `706`-`708`, passive (`A_P`=2) positive, active (1) negative. Archives up to 2021 list 5-digit second-order accounts, later ones 3-digit aggregates; a 3-digit row wins over the 5-digit rows under it.
- `fetchBanks` downloads a year's four 102 archives once, **differences consecutive cumulatives** into single-quarter net profit and revenue, stores each quarter-end's form 101 equity on every row (so the current P/B uses the latest quarter), and attaches year-end market cap + annual P/E (cap / full-year profit) + ROE (full-year profit / year-end equity × 100) to the Q4 row. `bankRows` takes the cap lookup as a function, so it is unit-tested without MOEX. A quarter whose form 101 is still unavailable within `equityGrace` (90 days) of its archive date is **not written**, so the next run retries it instead of storing it without equity forever (`equityPending`); older quarters are written without equity. Only quarters with form 102 data that some requested bank still lacks download form 101. ROE uses year-end (not average) equity, which includes the year's own profit (account 706). Existing rows get revenue/equity only with `FETCH_FORCE=1` — until then old Q4 rows still hold the former form 123 regulatory capital as `equity` and ROE.

Banks are keyed by CBR **REGN** (from `bank_tickers.txt`, embedded via `financialanalyzer.BankRegistry`); the ticker doubles as the MOEX secid for cap. EBITDA/debt have no meaningful bank equivalent and stay empty. Fixtures `internal/scraper/cbr/testdata/102-20240101.rar` (Sberbank REGN 1481: net profit 1493.1 bln = published RSBU; revenue 3414.5 = NII 2414.7 + fees 999.8) and `101-20240101.rar` (Sberbank equity 6340.7 bln) are the regression tests; synthetic in-test DBFs cover the parsers directly.

**Scheduled refresh and run log (`internal/fetcher`, `internal/scheduler`, `fetch_runs`, `/updates`).** `fetcher.Run(ctx, repo, Request, logger)` is the one entry to both pipelines + quotes + the cap-jump check; `Request`'s zero value refreshes every stored company. It returns a `Summary` per company: **updated**, **up to date** or **failed**, decided by `fetcher.classify` — any source error (a `girbo.PartialError`, a CBR download error other than `ErrNotPublished`) or save error makes a company failed even if some rows were written; "no new rows" is up to date only if the source knows the company (ГИР БО lists a year we already store, or the bank is in this run's form 102 archives, or nothing needed downloading). `fetcher.RunRecorded` wraps a run in a `fetch_runs` row (`kind` quotes|financials, `trigger` cli|schedule|catchup, `full_scope` = no explicit list, `status` running|ok|partial|failed|canceled|abandoned); the outcome is written on a context detached from the canceled run ctx, and every run first marks rows `running` for over 12 h as abandoned. `partial` = some company failed, or no quote was saved at all (CSV-only names failing their quote are routine and do not count). An empty DB (`fetcher.ErrNoCompanies`) is `ok` — nothing to refresh. `internal/scheduler` (started by `cmd/plot` when `SCHEDULER_ENABLED`) runs jobs sequentially in one goroutine at Moscow wall-clock slots (`Spec`: daily `HH:MM` or weekly `DAY HH:MM`; `models.Moscow` is a fixed UTC+3 zone). On startup it marks its own leftover `running` rows abandoned, waits 30 s, then catches up each job whose latest slot (`Spec.Prev`) has no completed (ok/partial) full-scope run since — financials first, since a financials run satisfies the quotes job too — and recomputes next slots so a caught-up slot never fires twice. `cmd/plot` cancels the scheduler and waits for it before closing the DB pool. Nothing prevents a manual `cmd/fetch` from overlapping a scheduled run (upserts make that harmless, just double load). `/updates` (Russian page) and `/api/fetch-runs` show the timetable, quote freshness and the latest 50 runs; they are unauthenticated, so `FetchRun.Error` (the raw error chain) is never served (`json:"-"`, the page only says that the run failed) and `Scope` holds only a list file's base name. Run kinds, triggers and `ScheduledJob` live in `models`, so `handlers` does not import the fetcher.

**Data quality (`internal/analytics/quality.go`).** `CheckRow`/`CheckHistory` flag suspicious figures: negative equity, P/E > 200 (negative P/E = a loss, not flagged), |ROE| > 100%, revenue < 1% of market cap, and net profit > revenue (the signature of a holding company's standalone RSBU, where income is subsidiaries' dividends; skipped for `cbr_102` rows, whose revenue is only a net-interest + fee proxy). Bank rows carry revenue, so their net margin, revenue growth and score parts are no longer NaN — bank scores are not comparable with industrials'. Each `Anomaly` lists the raw metrics it concerns; `Concerns`/`AnomaliesByLabel` map it onto derived metrics and chart labels. `IsComparable` treats `rsbu`/`cbr_102` as not comparable across companies; `csv`/`smartlab` and legacy NULL sources are neutral. `source` is row-level, last writer wins (see `models.QuarterData`). The chart page shows a Source column, highlights flagged cells (hover = reason) and draws flagged points as triangles; the dashboard shows a "Data quality" block. Note: code inside go-echarts `opts.FuncOpts` is JSON-encoded and injected verbatim, so it must not contain double quotes or backslashes — use `jsStringMap`/`jsString` in `handlers/chart.go` for dynamic strings.

**HTTP retries (`internal/scraper/httpx/`).** All scraper clients (girbo, moex, cbr) fetch through `httpx.Get`, which retries transport errors, 429 and 5xx with exponential backoff (`httpx.DefaultPolicy`: 3 attempts, 1s/2s, honours `Retry-After`, and gives up instead of retrying early when it exceeds `MaxDelay`); clients reset their rate-limit clock after the last attempt; other statuses return an `*httpx.StatusError` immediately (cbr maps 404 to `ErrNotPublished`). Each client's `Retry` field overrides the policy (tests use millisecond delays). Rate limiting (`Delay`) stays per client.

**Migrations.** Standard `golang-migrate` numbered up/down files in `migrations/`. Migrations run automatically on every startup of any binary; new migrations take effect with no separate step.
